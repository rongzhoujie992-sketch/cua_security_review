# Scholarly Admissibility and Publication-Quality Gate

The review uses **venue priority, not venue exclusivity**.

A record that passes topical title/abstract screening must also provide a credible scholarly evidence contribution before full-text retrieval.

## Publication priority

Priority is given to peer-reviewed work from the core venues named in the review methodology:

- IEEE Symposium on Security and Privacy
- ACM CCS
- USENIX Security
- NDSS
- NeurIPS
- ICLR
- ICML
- AAAI
- ACL
- EMNLP
- CHI
- The Web Conference (WWW)

Strong formal publication in adjacent areas is also admissible when the CUA-security evidence role is clear.

Publication venue is not an automatic inclusion or exclusion rule.

## Preprint admissibility

A preprint or under-review report proceeds only when the available evidence establishes a substantive contribution.

- Direct CUA-security work must report substantial empirical, benchmark, system, or formal evidence.
- Adjacent tool/MCP/memory/multi-agent/authorization work must also establish a specific executable-use security mechanism.
- Capability-only or narrow benchmark papers are retained only when they are necessary foundations for the general CUA setting.
- Conceptual-only, position, tutorial, or weakly evidenced records do not proceed to the core review corpus.

Where a full report was already available, scholarly admissibility was assessed from that full report under the same scope boundary.

Records whose admissibility still requires report-level inspection are retained as `UNCLEAR`.

## Version preference

When multiple reports describe the same study, one preferred report is selected for retrieval. Formal/publisher versions are preferred when available; otherwise the most complete identifiable report is retained. Alternate reports remain in the version-consolidation ledger and are not counted as separate candidate studies.
